# Shared documentation contract (schema 1)

`manifest.json` is the authored inventory, ordered as the original handbook. Its `schemaVersion` is 1, `version` is the documentation version (not necessarily the consuming binary's version), `pages` contains `{path,title,file}`, and `openapi` points at `reference/openapi.json`. Each title equals the Markdown h1; each file equals `content/` plus its exact legacy tool path. Preserve spelling and casing, notably `Neoism Agent/JSON Render.md`. Do not rename legacy paths when improving prose.

Canonical Markdown lives under `content/`. The OpenAPI contract lives under `reference/`. `bundle/content.json` is a checked-in generated tool resource, not a second authored source. Generate it with `node scripts/content-bundle.mjs` (no npm install required), then verify with `node scripts/content-bundle.mjs --check`. It includes `{schemaVersion:1,version,pages:[{path,title,content}],openapiSha256,sourcesSha256}`. The first entries are the exact manifest pages; generated operation pages use `API/<operationId>.md`; schemas use `API/Schemas/<name>.md`. Other component categories retain their OpenAPI names. Large definitions split deterministically into `.part-N.md` pages. API pages are bounded to approximately 25KB; references remain references, not recursively expanded schemas. No generated page replaces a handbook path.

`openapiSha256` hashes the exact bytes of the contract. `sourcesSha256` hashes manifest bytes, then each ordered guide's file path, NUL, UTF-8 content, NUL, then the OpenAPI file path, NUL, and bytes. This deliberately includes manifest order and version. Consumers should validate handbook bodies and the OpenAPI digest against the pinned sources; a Node/Vite dependency is not needed during Cargo compilation.

Build with `npm ci && npm run build`. The self-contained `dist/` directory is the same artifact on Vercel and on a loopback HTTP server. Serve its root, not only the `api/docs` subtree. The entry is `/api/docs/`; `/api/docs/reference/` contains static endpoint documentation enhanced by bundled Scalar. Canonical `/api/docs/guides/.../` pages contain readable HTML before JavaScript. Legacy `#guide/...` and `#reference` links redirect client-side. Serve directory indexes with trailing-slash redirects and return 404 for unknown docs routes; do not rewrite them to the marketing homepage. HTTP is required for ES modules; opening `file://` is not supported.

`dist/content.json` is byte-identical to `bundle/content.json`. `dist/manifest.json` copies the authored manifest. `dist/reference/openapi.json` is the original contract. `dist/artifact.json` inventories all other artifact files with byte sizes and SHA-256 digests. The generated asset directory is `docs-assets/` to avoid collisions with marketing assets. All required fonts, CSS, JavaScript, search text, reference data, and legal notices are local. Optional outbound source links are not runtime dependencies. Scalar telemetry, AI, MCP, try-request controls, and credential persistence are disabled; no analytics script is shipped. Local servers should bind loopback only and treat this as read-only reference content, not proxy requests to an agent server.

The website imports the already-built shared directory with its integration plugin. It must not apply content overlays, rebuild pages with website-only corrections, or maintain an independent renderer. Update both submodule pins after publishing a central docs commit. App packaging stages this directory at `resources/docs/`; app-specific server/bundling code belongs to the application repository.

Strict `script-src 'self'` is supported without `unsafe-eval`. The shared Zod instance is configured with its supported `jitless: true` mode before Scalar is dynamically imported. Do not move Scalar back to a static import: schema construction can otherwise trigger Zod's eval-capability probe before configuration, creating a CSP violation even when the probe catches its exception. The headless preview test enforces this strict script policy and asserts no security-policy violations. The lazy reference module uses ES2022 top-level await to preserve initialization order.
