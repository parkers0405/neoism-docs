# Sources and verification

The initial 45 guide paths and their order were migrated from `neoism-product-docs/src/lib.rs` and `neoism-workspace-index/src/welcome/` in the application checkout. The original source files were not modified during migration. `reference/openapi.json` is copied from `neoism-agent/openapi/v2.json`. The renderer, routes, shell, search, Scalar configuration, and Pastel Dark/Retro 95 theme originated in the website's `scripts/static-docs.ts`, `src/docs-*.ts`, `src/api-docs.*`, `src/scalar-reference.*`, and `src/guide-links.ts`.

The former website-only clarification layer is not used. Valid clarifications are canonical: daemon-owned saves are implemented in `neoism-workspace-daemon/src/crdt/sync.rs` and tested in `tests/crdt_save.rs`; shared code editing applies remote document state in `neoism-frontend/shared/src/editor/code/doc_sync.rs`. `shared/src/editor/crdt/presence.rs` supports optional selections, but `remote_presence.rs` constructs current presence with `selection: None`. We distinguish representable protocol fields from published client behavior. Shared session history and event-stream behavior are described without promising fine-grained terminal grants.

The older website overlay asserted full browser/mobile code and Markdown parity. The current application checkout's `neoism-frontend/web/src` no longer contains those browser source pumps, so this migration does not repeat that unverified promise or preserve the equally stale blanket claim that all browser/mobile Markdown is read-only. Instead, the canonical handbook explicitly requires compatible client builds and capability verification. `neoism-agent-cli/src/chat_tool_render.rs` emits session locators, but that alone does not verify an end-to-end current-client URL-opening flow. The sharing page now distinguishes connected shared chats from public transcripts and URL support. No screenshot or old website statement is treated as implementation evidence.
